# LACToS — reproducing Table 1

This branch contains exactly what is needed to reproduce **Table 1** of

> *LACToS: Local Anomaly deteCtion via Typicality of Superpixels* (ICLR 2027 submission)

i.e. pooled pixel-level **AUROC / AP / AUPRO** of LACToS and six baselines (PatchCore,
SimpleNet, SuperSimpleNet, EfficientAD, GLASS, DDAD) on three local-anomaly benchmarks:
CHAOS (abdominal CT with synthetic tumours), FFHQ (faces with prosthetics / atypical features)
and DVXray (baggage X-ray, scissors).

|---|---|---:|---:|---:|---:|---:|---:|---:|
| CHAOS | AUROC | 0.9297 | 0.7464 | 0.3786 | 0.6664 | 0.8318 | **0.9707** | 0.9620 |

## Setup

```bash
git clone -b release/lactos-table1 <this repository> LACToS && cd LACToS
tar xf /path/to/LACToS_table1_assets.tar            # -> LACToS_table1_assets/
ln -s $PWD/../LACToS_table1_assets assets           # or: export ASSETS=/path/to/LACToS_table1_assets

conda create -n lactos python=3.10 && conda activate lactos
pip install torch==2.0.1 torchvision==0.15.2 --index-url https://download.pytorch.org/whl/cu118   # the reference build
pip install -r requirements.txt                     # numpy, scipy, scikit-image, scikit-learn, pillow, pyyaml, omegaconf, kornia, pytest
bash scripts/00_check_assets.sh                     # verifies every file against SHA256SUMS
pytest tests -q -m "not requires_gpu and not slow"  # unit tests, no GPU
```

The exact environments the numbers were produced with are exported in `environment/`
(`ddad.txt` is the LACToS / EfficientAD / DDAD environment; the baselines need three more, see stage 3).

## Reproduce Table 1: the scripts, in order

| Stage | Script | What it does | Needs | Time (1 GPU) |
|---|---|---|---|---|
| 0 | `scripts/00_check_assets.sh` | checks the bundle (layout, counts, SHA-256) | bundle | 1 min |
| 1 | `scripts/10_sample_{ct,xray,ffhq}.sh` | **optional**: re-sample the DPS reconstructions | diffusion priors | ~2 / ~4 / ~8 GPU-h |
| 2 | `scripts/20_score_lactos.sh` | LACToS scoring at the paper's operating points → per-image delta maps | recons, AEs | ~1 h |
| 3 | `scripts/30_run_baselines.sh` | the six baselines at the paper's settings → per-image raw maps | baseline ckpts, 4 envs | ~1.5 h |
| 4 | `scripts/40_make_table1.py` | pool, blur, metrics; writes `results/table1.{json,md,tex}` and diffs against the paper | stages 2+3 | 5 min |

```bash
GPU=0 bash scripts/20_score_lactos.sh                 # or one benchmark: CT | xray | ffhq
GPU=0 bash scripts/30_run_baselines.sh                # or one benchmark: ffhq | ct | xray
python scripts/40_make_table1.py                      # --only lactos | --only baselines
```

Stage 1 is not needed to reproduce the table: the reconstructions it would produce are
shipped in `recons/`. It is there so that the full pipeline (diffusion prior → DPS
reconstructions → LACToS) can be re-run; `sampling/README.md` explains the samplers and
how to score your own reconstructions (`RECON_ROOT=results/recons_mine`).

Stage 3 needs the official implementations of PatchCore, SimpleNet, GLASS and SuperSimpleNet
(`bash scripts/fetch_third_party.sh` clones them at the commits we used) and their environments
(`environment/patchcore.txt`, `simplenet.txt` — also used for GLASS —, `ssn_env.txt`; DDAD and
EfficientAD run in the LACToS environment). DDAD and EfficientAD run in the
interpreter that runs the script (your `lactos` env); point the script at the other three with
`PY_PATCHCORE=... PY_SIMPLENET=... PY_SSN=...` or `CONDA_ENVS=/path/to/conda/envs` (the env names
`patchcore`, `simplenet`, `ssn_env`).

All scripts take `GPU=<index>`, `OUT=<results dir>` and `ASSETS=<bundle dir>`; stages 2 and 3
are resumable per benchmark and can run in parallel on different GPUs. Outputs:

```
results/lactos_maps/<bench>/<tag>/<set>/samples_<id>.npz     stage 2: delta_map, gt_mask, valid_mask per image
results/baseline_maps/<bench>/<method>/<setting>/<set>__<id>.npz   stage 3: raw quantities per image
results/table1.{json,md,tex}                                  stage 4
```

## How the numbers are computed

* **Metrics** (`full_metric_table.py`, used identically for every method): all valid pixels
  of all test images of a benchmark are pooled; AUROC and AP over that pool; AUPRO is the
  area under the per-region-overlap curve up to FPR 0.3, normalised by 0.3. Anomalous and
  anomaly-free images are pooled together (CHAOS 100 + 100 slices, FFHQ 50 + 50 faces, DVXray
  72 + 72 bags); CHAOS pixels outside the body mask are excluded. Every map is smoothed with a
  Gaussian before pooling (LACToS: σ in the table below; baselines: each method's published
  composition, i.e. its internal σ = 4 blur followed by σ = 5).
* **LACToS operating points** (paper Table 5; `docs/HYPERPARAMETERS.md` has every flag):

  | | superpixel size | draws M | histogram σ | bins (intensity × feature) | λ | spatial σ |
  |---|---:|---:|---:|---|---:|---:|
  | CHAOS | 100 | 5 | 0.5 | 16 × 64 | 1 | 2 |
  | FFHQ | 20 | 20 | 1 | 16 × 32 | 0.25 | 5 |
  | DVXray | 10 | 20 | 0 | 16 × 16 | 0 | 5 |

  λ weights the feature-typicality term against the intensity term; λ = 0.25 (FFHQ) is composed
  in stage 4 from a full and an intensity-only run of stage 2, λ = 0 (DVXray) is the
  intensity-only run.
* **Baseline settings** (paper Table 6): PatchCore k = 1; EfficientAD α = 0 / 0.7 / 0.2
  (CHAOS / FFHQ / DVXray); DDAD T = 250, skip 25, η = 1 with (w, v) = (2, 1) / (2, 4) / (4, 4);
  SimpleNet, SuperSimpleNet and GLASS at their defaults.

## Caveats you should know before quoting the numbers

* **GLASS** checkpoints were selected on the test set by the upstream training code
  (`ckpt_best`); every other method's checkpoint is the final or a fixed epoch. The GLASS row is
  therefore optimistic relative to the others.
* **DVXray "good" images are training images** of every method (the 5,000 weapon-free bags);
  the pooled DVXray numbers are measured on training data for the anomaly-free half.
* **CHAOS body masks** of the normal slices differ slightly between the LACToS evaluation and
  the baseline evaluation (two versions of the body segmentation, IoU 0.94–0.98; the anomalous
  slices use identical masks). Both are shipped and used as in the paper (`docs/PROVENANCE.md`).
* The CHAOS LACToS row was computed with the autoencoder's first layer folded into the feature
  extractor (`evaluate.py --ae_encode folded`, see its docstring); it is the same function
  evaluated in a different float32 order, which moves a handful of latent values across
  histogram-bin edges. The FFHQ row used the direct evaluation. Stage 2 uses the right one per
  dataset; `docs/HYPERPARAMETERS.md` lists what the other choice gives.
* Redistribution of the test images (FFHQ photographs and movie stills, CHAOS- and
  DvXray-derived images) is subject to the respective dataset licences.

## Repository layout

```
scripts/            00_check_assets.sh  10_sample_*.sh  20_score_lactos.sh  30_run_baselines.sh  40_make_table1.py  fetch_third_party.sh
evaluate.py         LACToS scorer (reconstructions -> superpixels -> typicality -> delta map)
ood/                data loading, superpixels, ResNet pixel embeddings, typical-set scoring, samplers (DPS for FFHQ)

configs/            evaluate.py configs per dataset; configs/recon/ = FFHQ sampler configs
sampling/           DPS samplers: sampling/dps (CHAOS, DVXray: guided-diffusion + sample_fast.py), generate_recons.py (FFHQ), wire_recons.py

docs/               HYPERPARAMETERS.md  PROVENANCE.md  BUNDLE.md  REPRODUCIBILITY.md
environment/        pip freeze of the four environments
release_tools/      how the bundle was staged from the lab's files (maintainers only)
```
